# 阳和财务系统 · 运维手册

面向负责维护这套系统的人。日常使用者看《使用说明》就够了；记账的人看《使用手册》。

> 本手册针对**单机 / 单台 Windows 电脑当服务器**这种形态。
> 如果要在 NAS 上用 Docker 部署给全单位使用，请看《部署手册-NAS》。

## 一、端口与目录对照

| 项目 | 离线单机运行 | 正式使用 |
| --- | --- | --- |
| 应用端口 | 18080（仅 127.0.0.1） | 8080（0.0.0.0） |
| 数据库端口 | 55432（仅 127.0.0.1） | 55433（仅 127.0.0.1） |
| 数据库目录 | `data\demo\pg\` | `data\prod\pg\` |
| 日志 | `logs\demo\` | `logs\prod\` |
| 备份 | 不自动备份 | `backups\prod\` |
| 口令文件 | `secrets\demo.pass` | `secrets\prod.pass` |

数据库始终只监听 `127.0.0.1`，**不会暴露到局域网**，外部只能通过应用的 8080 端口访问。

## 二、启动与停止

### 客户看到的入口

根目录的 **`阳和财务系统.hta`**（显示为「HTML 应用程序」）。双击后的行为：

1. 显示启动页（HTML 界面，无黑框闪烁）
2. 通过 `WScript.Shell` 以**最小化**方式拉起 `scripts\start.ps1 -Mode prod`——这个最小化的控制台窗口就是服务本体
3. 用 `MSXML2.XMLHTTP` 轮询 `http://127.0.0.1:8080/healthz`，就绪后 `ShellExecute` 打开默认浏览器
4. 启动页上提供「打开阳和财务系统」「停止服务」，底部另有「单机体验（18080）」入口

服务已在运行时双击图标不会再起一份，1 秒内直接跳转浏览器。

> 为什么是 `.hta` 而不是 `.html`：普通网页受浏览器沙箱限制，无法启动本地程序。HTA 是 Windows 自带的「HTML 应用程序」，本质仍是 HTML，但以受信任的本地应用身份运行，具备调用系统接口的能力。若被安全软件拦截，启动页会提示改用 `工具\` 下的 bat。

### 命令行 / 排障入口

根目录 `工具\` 下保留了四个 bat，需要看完整日志或启动页不可用时使用：

| 文件 | 作用 |
| --- | --- |
| `1-单机体验.bat` | `start.ps1 -Mode demo` |
| `2-正式使用.bat` | `start.ps1 -Mode prod` |
| `3-停止运行.bat` | `stop.ps1 -Mode all` |
| `4-立即备份.bat` | `backup.ps1 -Mode prod` |

也可以直接跑脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start.ps1 -Mode prod
powershell -ExecutionPolicy Bypass -File scripts\stop.ps1 -Mode all
powershell -ExecutionPolicy Bypass -File scripts\status.ps1   # 端口/进程/健康检查/数据体积/最近备份
```

启动脚本的行为：

1. 检查路径、端口、运行库
2. 数据库未初始化则自动 `initdb`（仅首次）
3. 数据库已在运行则**复用**，不重复启动
4. 启动应用并轮询 `/healthz`，就绪后打开浏览器（`-NoBrowser` 可关掉）
5. 窗口跟随输出应用日志；`Ctrl+C` 或关闭窗口会先停应用再停数据库

> 直接点窗口右上角 × 时，Windows 只给几秒退出时间，数据库可能来不及干净退出。下次启动会自动清理残留进程记录并做 WAL 恢复，数据不会坏，但建议用「停止服务」或 `工具\3-停止运行.bat`。

## 三、改端口
端口以 `config\prod.yaml` 的 `server.addr` 为准，启动脚本会自动读取：

```yaml
server:
  addr: "0.0.0.0:9000"   # 改成你要的端口
```

改完重新双击 2 号图标即可。正式模式会按新端口重新添加防火墙规则。

> 数据库端口固定在脚本里（55432/55433），一般不需要改，也不建议改。

## 三之二、会计准则选项

本交付版本**只开放「政府会计制度（行政事业单位）」**，建账套时看不到其他准则。这是 `config\<模式>.yaml` 里的白名单控制的：

```yaml
standards:
  dir: ""
  allow: ["gov_accounting"]     # 只允许政府会计制度
```

- 想同时开放小企业会计准则：改成 `allow: ["gov_accounting", "small_enterprise"]`
- 想全部开放：写成 `allow: []`
- 写错编码（比如 `gov_account`）会**启动失败并报错**，这是刻意设计，避免拼写错误导致所有准则都不可用
- 也可以用环境变量覆盖：`YANGHE_FINANCE_STANDARDS_ALLOW=gov_accounting,small_enterprise`

> 注意：账套一旦建立，其准则由数据库里的 `standard_code` 决定，改白名单不会影响已有账套。

## 四、局域网访问排查（同事打不开）

按顺序检查：

1. **网络类型**：Windows 设置 → 网络和 Internet → 当前网络属性，把「公用网络」改成「专用网络」。公用网络下 Windows 默认拦截入站连接。
2. **防火墙规则**：管理员 PowerShell 执行

   ```powershell
   netsh advfirewall firewall show rule name="阳和财务系统-正式使用-TCP8080"
   ```

   没有输出说明规则没加上，执行：

   ```powershell
   netsh advfirewall firewall add rule name="阳和财务系统-正式使用-TCP8080" dir=in action=allow protocol=TCP localport=8080 profile=private,domain
   ```

3. **IP 是否对**：`ipconfig` 看 IPv4 地址；`scripts\status.ps1` 也会列出可用的局域网地址。
4. **同一网段**：确认双方在同一个局域网（不是访客 Wi-Fi）。

## 五、备份

### 手动备份

双击 `4-立即备份.bat`，或：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1 -Mode prod
```

- 格式：`pg_dump -Fc`（与 NAS 侧一致），文件名 `yanghe-finance-yyyyMMdd-HHmmss.dump`
- 先写 `.partial` 再改名，避免半截文件被当成有效备份
- 生成后用 `pg_restore -l` 校验可读性
- 自动清理超过 30 天的旧备份（`-KeepDays` 可调）

### 自动备份（可选）

用计划任务每天凌晨 2 点备份：

```powershell
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\yanghe-finance\scripts\backup.ps1" -Mode prod'
$trigger = New-ScheduledTaskTrigger -Daily -At 02:00
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType S4U -RunLevel Limited
Register-ScheduledTask -TaskName 'Yanghe\Backup' -Action $action -Trigger $trigger -Principal $principal
```

> 本机备份不算真正的备份。请每周把 `backups` 目录同步到 NAS、移动硬盘或网盘。

### 恢复

建议先双击 `3-停止运行.bat` 把服务停干净，再执行恢复：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 -Mode prod -File "D:\...\yanghe-finance-20260101-020000.dump"
```

会提示输入 `YES` 确认，然后停应用 → 删库 → 建库 → 导入 → 完成。恢复后已登录用户需要重新登录（会话密钥存在数据库里），重新双击 2 号图标即可继续使用。

> 恢复过程中不要关闭窗口，也不要同时运行启动脚本。

## 六、忘记管理员密码

系统没有内置的「找回密码」入口。处理方式：

- 如果还有**另一个系统管理员**账号：用它登录，在「用户管理」里重置密码。
- 如果没有其他管理员：只能从备份恢复（恢复到有可用管理员的时点），或联系技术支持通过数据库重置。

> 这是当前版本的已知限制，建议至少保留两个管理员账号。

## 七、常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 提示 `vcruntime140.dll` 缺失 / 数据库起不来 | 安装 `pgsql\vcredist\VC_Redist.x64.exe`，重启电脑后重试 |
| 提示端口 8080 被占用（含 PID） | 按提示的 PID 用任务管理器结束进程，或改端口 |
| 提示「安装路径包含中文」 | 把整个文件夹移到纯英文路径（如 `C:\yanghe-finance`），路径中不能有中文；空格可以 |
| 提示「不能放在网络路径上」 | 把整个文件夹复制到本机硬盘（不要放网络盘、U 盘、同步盘） |
| 初始化卡住很久 | 机械硬盘或杀毒软件实时扫描所致，等 1–2 分钟；若超过 5 分钟，看 `logs\prod\` 日志 |
| 上次关窗口后再启动报错 | 脚本会自动清理残留记录；若仍失败，用 `stop.ps1 -Mode all` 后再启动 |
| 杀毒软件隔离了 yanghe-finance.exe / postgres.exe | 把安装目录加入杀毒软件排除项；SmartScreen 提示时选「更多信息 → 仍要运行」 |
| 页面 404 或白屏 | 确认 `web\index.html` 存在；确认没有把 `web` 目录单独移走 |
| 提示「服务已在运行」但打不开页面 | 运行 `scripts\status.ps1` 看健康检查；必要时 `stop.ps1 -Mode all` 重启 |

## 八、Windows 7 客户端

服务端（Go 程序 + PostgreSQL）**不能运行在 Windows 7 上**：Go 1.21 起要求 Windows 10+，PostgreSQL 16 的发布说明也明确要求 Windows 10+。因此 Win7 只作为访问端。

**可行方案**：用交付包里的 `yanghe-finance-client-<版本>.zip`。它内置 Firefox ESR 115（Mozilla 最后一个支持 Win7 的长期支持版），免安装、免管理员权限、不写注册表，配置只需改 `server.ini` 里的一行地址。

**为什么不能直接用 IE**：前端是 Vue 3，Vue 3 从设计上不支持 IE11；IE11 也无法运行 ES2020 语法的产物。这不是配置问题，无解。

**如果客户希望自己装浏览器**（不想要绿色包），可选：

| 浏览器 | 说明 |
| --- | --- |
| Chrome 109 | Google 最后一个支持 Win7 的版本，之后不再更新 |
| Firefox ESR 115 | Mozilla 最后支持 Win7 的版本，可从 archive.mozilla.org 获取 |
| 360 极速 / QQ 浏览器（极速模式） | 内部是 Chromium 内核，需 ≥107 内核；实际表现需现场验证 |

> Win7 上的浏览器都已停止安全更新，只建议在可信局域网内使用。

### 构建客户端包（仅维护者需要）

`deploy/windows/vendor/` 不入库，需要在构建机上重新获取一次浏览器：

```powershell
# 1. 下载 Firefox ESR 115 中文安装包（Win7 最后可用版本）
#    https://archive.mozilla.org/pub/firefox/releases/115.45.0esr/win64/zh-CN/
#    Firefox Setup 115.45.0esr.msi

# 2. 静默安装到本机（临时），再把安装目录复制成绿色版
msiexec /i "Firefox Setup 115.45.0esr.msi" /qn
Copy-Item 'C:\Program Files\Mozilla Firefox' 'deploy\windows\vendor\firefox-115.45.0' -Recurse

# 3. 卸载本机安装（绿色版已复制，不影响）
msiexec /x "Firefox Setup 115.45.0esr.msi" /qn

# 4. 打包客户端
powershell -ExecutionPolicy Bypass -File deploy\windows\package-client.ps1 -Version 1.0.0
```

产物：`build\release\yanghe-finance-client-<版本>.zip`。交付前记得把 `server.ini` 的示例地址改成客户的实际地址。

## 九、日志与排障信息
- 应用日志：`logs\prod\app-yyyyMMdd-HHmmss.log`（标准错误，含启动、迁移、请求错误）
- 数据库日志：`logs\prod\pg.log`
- 交付版本信息：根目录 `VERSION.txt`
- 启动失败原因：`run\prod\start-error.txt`（启动页显示的也是这份内容，每次启动会先清空）

提交问题时请附上：`VERSION.txt` 内容 + 最近一个应用日志的末尾 50 行 + `status.ps1` 的输出。

> 服务窗口在启动失败后会自动关闭，原因同时写在启动页和上面的 `start-error.txt` 里；
> 需要完整过程日志时，用 `工具\2-正式使用.bat` 启动，那个窗口不会自动关闭。
