# 架构说明

本文说明柠檬账的技术选型、模块边界、数据模型与扩展方式。新增功能前请先读“扩展点”一节。

## 1. 目标与约束

| 约束 | 对应设计 |
| --- | --- |
| 部署在局域网 NAS（非开发机），资源有限，可能是 ARM | 单个 Go 二进制 + PostgreSQL，Docker Compose 一键部署，镜像支持 amd64/arm64 |
| 多人同时在局域网内使用 | B/S 架构，浏览器访问；数据库事务 + 账套级行锁保证记账串行一致 |
| 以柠檬云为功能与交互基准，并增加平行记账 | “核算账簿”是一等概念，单体系账套 1 个账簿，平行记账账套多个 |
| 长期迭代、可配置、少硬编码 | 模块化单体；会计准则、报表、结转规则、平行记账规则、角色权限、菜单全部是数据/配置 |

## 2. 技术栈

- **后端**：Go，`chi` 路由，`pgx` 直连 PostgreSQL（手写 SQL，不用 ORM），`shopspring/decimal` 处理金额
- **数据库**：PostgreSQL 16，金额字段 `numeric(18,2)`；迁移脚本内嵌在二进制中，启动时自动执行
- **前端**：Vue 3 + TypeScript + Vite + Element Plus + Pinia
- **部署**：`deploy/docker-compose.yml`（数据库、应用、每日备份三个容器）

金额在后端全程用十进制类型，JSON 中以字符串传输，前端以“分”为单位做整数运算，任何环节都不经过二进制浮点数。

## 3. 总体结构

```
浏览器 (Vue SPA)
   │  HTTP/JSON  /api/v1
   ▼
cmd/lemon ── internal/app（装配：创建模块、挂载路由）
   │
   ├── internal/modules/      业务模块（每个模块 = 一个包）
   │     iam        用户、登录
   │     standard   会计准则模板（读取 YAML）
   │     book       账套、成员权限、会计期间、账套级配置存储
   │     account    会计科目
   │     auxiliary  辅助核算（类别、项目、科目绑定）
   │     voucher    凭证、平行记账规则与分录生成
   │     ledger     余额引擎、期初、科目余额表/明细账/总账（读模型）
   │     closing    期末结转、结账检查、结账/反结账
   │     report     报表引擎
   │     dataio     批量导入（科目、辅助核算项目、期初）
   │
   ├── internal/platform/     与业务无关的基础设施
   │     config / db / httpx / auth / audit
   │
   ├── internal/kernel/       共享的最小领域概念（期间、借贷方向）
   ├── configs/               内嵌的默认配置（准则模板、角色）
   └── migrations/            内嵌的数据库迁移
```

### 模块依赖（只允许自上而下）

```
report ──► ledger ──► auxiliary ──► account ──► book ──► standard
closing ─► ledger, voucher  ▲
voucher ────────────────────┘
所有模块 ─► platform, kernel
```

规则：

1. **模块之间只通过对方导出的 Service 方法交互**，不直接读写对方的表。唯一例外是 `ledger`：它是读模型，直接汇总凭证分录表以保证查询效率。
2. **反向依赖用接口或钩子倒置**。例如“启用辅助核算的科目不能增加下级”是 `auxiliary` 的约束，通过 `account.OnAddChild` 钩子注册，`account` 不需要认识 `auxiliary`。例如报表需要知道“哪些凭证是结转损益凭证”，由 `report.ActivityFilter` 接口声明、`closing` 实现、`app` 连线。
3. **跨模块事务通过 context 传播**。模块内部一律用 `db.Q(ctx)` 取执行器，上层用 `db.Tx(ctx, fn)` 包裹即可让多个模块的写操作落在同一事务（见期末结转：删旧凭证 → 取余额 → 生成新凭证）。
4. **权限在路由上声明**：`book.Require("voucher:write")`。权限点 → 角色的映射在 `configs/roles.yaml`。

## 4. 核心数据模型

```
books 账套 ─┬─ ledgers 核算账簿（FIN 财务会计 / BUD 预算会计 …）
            ├─ account_categories 科目类别（is_pl 标记损益/收支类）
            ├─ accounts 科目（归属某账簿；树形；末级才能记账）
            ├─ opening_balances 期初（末级科目）
            ├─ periods 期间（是否已结账）
            ├─ vouchers 凭证 ── voucher_lines 分录（每行带 ledger_id）
            ├─ aux_types 辅助核算类别 ── aux_items 项目
            │    account_aux_types 科目启用的类别
            │    voucher_line_aux  分录上的项目
            │    opening_aux(+_items) 按项目组合的期初
            ├─ parallel_rules 平行记账规则
            ├─ book_configs 账套级配置（kind=report / closing_rule，JSON 定义）
            └─ book_members 成员与角色
```

关键设计决定：

- **余额不落表**。余额 = 期初 + 凭证分录实时汇总（`ledger.Balances`）。没有“过账”步骤，凭证保存即生效（与柠檬云一致），也不存在余额表与凭证不一致的可能。若将来数据量需要，可在 `Balances` 内部加期间快照，对调用方透明。
- **凭证的 `source` 字段**标识来源（`manual`、`closing:<规则编码>`，以后还有固定资产、工资等业务模块）。利润表类报表据此剔除结转凭证，取“实际发生额”。
- **建账即复制**。准则模板的全部内容在建账时复制进账套，此后账套独立演化；修改模板文件不影响已有账套。
- **账套级行锁**。所有记账类写操作先 `select … for update` 锁住账套行，凭证取号、结账检查等因此不需要额外的并发控制。

## 5. 平行记账

平行记账在本系统中被建模为“**一个账套、多个核算账簿、一张凭证**”：

- 科目归属于某个账簿；凭证分录的账簿由其科目决定。
- 保存凭证时**每个账簿内的分录各自借贷平衡**。
- 科目余额表、总账、报表模板、结转规则都按账簿取数。

内置的《政府会计制度》模板包含财务会计（权责发生制）与预算会计（收付实现制）两个账簿。

**分录生成**（`voucher.SuggestParallel`）：录入财务会计分录后点击“生成平行记账分录”。

1. 触发条件：财务会计分录中出现“现金类”科目（库存现金、银行存款、零余额账户用款额度等，科目上的 `is_cash` 标记）——即发生了纳入预算管理的现金收支。
2. 映射：每条财务会计分录按规则生成一条**同方向、同金额**的预算会计分录。
3. 规则查找：先找科目本身，再逐级找上级；同级内限定方向（仅借方/仅贷方）的规则优先于通用规则。例如“短期借款”贷方 → 债务预算收入，借方 → 债务还本支出。
4. 生成结果只是建议，用户核对修改后随凭证一起保存；没有规则的科目会给出提示。

**完整性检查**（账套设置）：财务会计分录动用了现金类科目却没有预算会计分录时，可选择不检查 / 保存时提示 / 禁止保存。

这套模型同样适用于“多准则并行”（如企业准则账 + 税务账）：新增一个账簿和一组映射规则即可，无需改代码。

## 6. 辅助核算

- **类别与项目**：类别（客户、供应商、职员、部门、项目…）由准则模板预置，账套内可自定义；每个类别下维护项目档案。
- **科目绑定**：末级科目可启用一个或多个类别。启用后该科目的每条分录、每笔期初都必须为每个类别指定一个项目。
- **约束**：科目已有凭证或期初数据后不能调整绑定（否则历史分录会缺项目）；启用辅助核算的科目不能再增加下级科目。已被使用的项目不能删除，只能停用。
- **期初**：启用辅助核算的科目按“项目组合”录入，科目期初为各组合之和，由系统自动汇总——余额引擎因此无需感知辅助核算。
- **账表**：辅助核算余额表（类别 → 项目 × 科目）、辅助核算明细账（项目的逐笔分录）。
- **期末结转**：来源科目启用了辅助核算时，按项目组合逐一转平；结转目标科目不能启用辅助核算。
- **平行记账**：生成目标账簿分录时，目标科目启用的类别若来源分录也有，则沿用同一项目。

## 7. 扩展点

| 想做的事 | 怎么做 | 需要改代码吗 |
| --- | --- | --- |
| 增加一套会计准则（如企业会计准则、民间非营利） | 在 `configs/standards/` 加一个 YAML，或放到外部目录并设置 `LEMON_STANDARDS_DIR` | 否 |
| 增加/调整报表 | 模板里加 `reports` 项；已有账套通过 `PUT /books/{id}/reports/{code}` 保存模板 | 否 |
| 调整结转规则（目标科目、来源范围、频率） | `PUT /books/{id}/closing-rules/{code}` | 否 |
| 调整平行记账映射 | 界面“设置 → 平行记账规则” | 否 |
| 增加角色或调整角色权限 | 复制 `configs/roles.yaml` 修改，用 `LEMON_AUTH_ROLES_FILE` 指向它 | 否 |
| 增加账套参数 | `book.Settings` 加字段 + 默认值，前端账套设置页加表单项 | 少量 |
| 增加一个业务模块（固定资产、出纳…） | 新建 `internal/modules/<名称>`，在 `app.New` 中创建并挂载路由；需要生成凭证时调用 `voucher.Service.Save` 并使用自己的 `source` 前缀；前端在 `config/menu.ts` 与 `router.ts` 各加一项 | 是，但不动既有模块 |
| 增加辅助核算类别 | 界面“设置 → 辅助核算 → 新增类别”；或在准则模板 `aux_types` 中预置 | 否 |
| 科目增加数量、外币核算 | `accounts.attrs`、`voucher_lines.attrs` 两个 JSONB 字段已预留 | 是 |

### 导入导出

- **导出**在前端完成：`ExportButton` 组件把页面上的账表（`table.sheet`）原样写成 Excel，新增账表页面放一个按钮即可，无需后端配合。
- **导入**分两段：前端用 `ImportDialog` 解析 Excel 为行数据，后端 `dataio` 模块逐行校验并调用各业务模块的正常写入路径——导入与手工录入因此遵循完全相同的规则。一次导入在同一事务内执行，有任何一行出错则整批回滚并返回逐行错误。
- 新增一种导入：在 `dataio` 加一个 `ImportXxx` 方法和路由，前端页面放一个 `ImportDialog` 并提供“下载模板”和“提交”两个函数。

### 结转规则语法

```yaml
closing_rules:
  - code: bud_fiscal
    name: 结转财政拨款收支
    ledger: BUD
    frequency: yearly            # monthly 每月 | yearly 仅 12 月
    sources:                     # 来源选择器，命中任一即入选
      - {accounts: [6001]}       # 科目编码（含下级）
      - {categories: [bud_expense], aux: {fund_nature: "01"}}   # 科目类别 + 辅助核算项目
    target: 8101                 # 转入的末级科目
    summary: 年末结转财政拨款预算收支
    exclude_from_activity: true  # 生成的凭证不计入报表的“实际发生额”
    required: true               # 结账前来源必须已转平
    only_if: credit              # 可选：仅当来源合计为贷方（debit 为借方）余额时才结转
```

- `source_categories` / `source_accounts` 是不带辅助核算条件时的简写。
- 选择器带 `aux` 条件时只结转包含该项目的余额；科目未启用该类别时默认不入选，加 `unbound: true` 则整体入选（用于“未区分的一律按其他处理”）。
- 规则按排列顺序执行，“一键结转”在同一事务内依次执行本期适用的全部规则，后面的规则能看到前面生成的凭证。

**预算会计年末结转**（《政府会计制度》模板）按“资金性质”辅助核算分流：

| 顺序 | 来源 | 转入 |
| --- | --- | --- |
| 1 | 财政拨款预算收入；各项支出中的财政拨款资金 | 8101 财政拨款结转 |
| 2 | 各项预算收入、支出中的非财政专项资金 | 8201 非财政拨款结转 |
| 3 | 经营预算收入、经营支出 | 8401 经营结余 |
| 4 | 其余全部预算收支（其他资金，及未区分资金性质的科目） | 8501 其他结余 |
| 5 | 其他结余；经营结余（仅盈余时） | 8701 非财政拨款结余分配 |
| 6 | 非财政拨款结余分配 | 8202 非财政拨款结余 |

行政单位没有结余分配环节，把第 5 步“其他结余转入结余分配”的目标科目改为 8202 即可。提取专用基金在第 6 步之前手工录入凭证。财政拨款结转内部明细的冲销、结转转结余等需按批复手工处理。

### 报表模板语法

```yaml
reports:
  - code: balance_sheet
    name: 资产负债表
    ledger: MAIN            # 取数账簿
    layout: two_side        # two_side 左右对照 | list 单列
    columns:
      - {key: end,   name: 期末余额, at: period_end}   # 时点列：period_end | year_begin
      - {key: begin, name: 年初余额, at: year_begin}
      # 区间列写 range: period（本期）| ytd（本年累计）
    rows:
      - {key: 4, name: 应收账款, side: left, nat: D, terms: ["1122:DB", "2203:DB"]}
      - {key: 15, name: 流动资产合计, side: left, bold: true, sum: "1+2+3+4"}
    checks:
      - {name: 资产 = 负债 + 权益, left: 30, right: 53}
```

`terms` 中每一项为 `[+|-](科目编码|@科目类别)[:取数规则][#辅助核算类别=项目编码]`，例如：

- `1001`、`-1407`、`1122:DB` —— 科目取数
- `@fin_revenue:YAMT` —— 该科目类别下全部一级科目之和
- `@bud_expense:YAMT#fund_nature=01` —— 只统计带“资金性质 = 01”的期初与分录

| 规则 | 含义 | 适用列 |
| --- | --- | --- |
| （省略） | 时点列按行的 `nat`（D 借方净额 / C 贷方净额）；区间列为实际发生额 | 全部 |
| `D` / `C` | 借方净额 / 贷方净额 | 时点 |
| `DB` / `CB` | 末级科目中借方余额合计 / 贷方余额合计（往来重分类） | 时点 |
| `AMT` | 实际发生额，按科目方向，剔除结转凭证 | 区间 |
| `DA` / `CA` | 借方 / 贷方实际发生额 | 区间 |

| `YBD` / `YBC` | 年初借方 / 贷方净额 | 任意（绝对规则） |
| `ED` / `EC` | 期末借方 / 贷方净额 | 任意（绝对规则） |
| `YAMT` / `YDA` / `YCA` | 本年累计实际发生额：按科目方向 / 借方 / 贷方 | 任意（绝对规则） |

- `sum` 为行间公式，引用其他行的 `key`，支持 `+` `-`。
- **计算列**：列不写 `at` / `range` 时，取数项必须用绝对规则。适合各行口径不同的报表（如预算结转结余变动表：有的行取年初、有的行取本年发生、有的行取年末）。
- **矩阵式报表**：行上用 `cells: {列key: [取数项]}` 按列分别取数；列上用 `sum: "a+b+c"` 定义列间公式（如净资产变动表的“净资产合计”）。
- “实际发生额”剔除所有标记了 `exclude_from_activity` 的结转凭证。

模板保存时会校验语法、引用与循环依赖。

## 8. 安全与数据保护

- 密码以 bcrypt 存储；登录签发 JWT，签名密钥首次启动自动生成并保存在数据库（也可用配置指定）。
- 账套访问需成员身份，写操作按角色权限点校验；系统管理员可访问全部账套。
- 关键操作写入 `audit_logs`（登录、凭证增删改审、结账、科目与规则变更等）。
- 已结账期间在服务端强制只读；已审核凭证须先取消审核才能改。
- 备份容器每日 `pg_dump`，保留天数可配。建议再配合 NAS 快照。
- 系统面向可信局域网，默认 HTTP。如需跨网访问，请在前面加反向代理并启用 HTTPS。

## 9. 迭代路线

**第一阶段（已完成）—— 总账核心**

账套与准则模板、科目、期初、凭证（录入/审核/整理凭证号）、平行记账、科目余额表/明细账/总账、期末结转与结账、资产负债表/利润表等报表、用户与权限、操作日志、NAS 部署与备份。

**第二阶段 —— 核算深度**

- ✅ 辅助核算（客户、供应商、部门、项目、职员及自定义类别）与辅助账
- 数量核算、外币核算与期末调汇
- 凭证模板、常用摘要、凭证复制/冲销、附件上传
- 现金流量表（按现金流量项目指定）
- ✅ 预算会计年末结转（按“资金性质”分流，规则可配置；一键结转）
- ✅ 行政事业单位专用报表：净资产变动表、预算结转结余变动表（仅“本年数”）
- 财政拨款预算收入支出表（需功能分类、项目维度）；报表“上年数”列
- 报表公式、结转规则的可视化编辑界面
- ✅ Excel 导入（科目、辅助核算项目、期初）与账表导出
- 凭证导入、凭证套打

**第三阶段 —— 业务模块**

- 出纳：日记账、银行对账
- 固定资产：卡片、折旧计提自动生成凭证
- 工资、发票、往来核销
- 年结与跨年查询优化（余额快照）

**持续项**：企业会计准则、民间非营利组织会计制度等模板；操作日志查询界面；数据导入（科目、期初、凭证）。
